# 执行边界

[English](execution-boundary.md) | 简体中文

执行边界将权威开发控制与提供商本地执行细节分离。

```text
权威目标 / 状态图（CLE）
  -> 受限的序列化 WorkOrder
  -> 提供商资格与执行生命周期（CLF）
  -> 标准化回执与证据
  -> 确定性验证、策略与权限检查（CLE）
  -> 接受状态迁移或 HOLD
```

CLF 可以解析合格提供商并管理执行侧生命周期，但不会修改 CLE 的权威 DAG。CLE 可以在 WorkOrder 中请求能力；它不拥有提供商进程/会话生命周期，也不把提供商本地工作流结构当作权威状态。

内部提供商可以使用子智能体、本地任务 DAG 或其他实现策略。这些细节是可替换的，并受已准入 WorkOrder 的约束；它们不能扩大资源、权限、预算、截止时间或委托。未知外部状态应 fail-closed。

架构与提供商无关。当前提供商验证仍可能主要面向 Codex；这一观察不是架构依赖，也不是生产声明。
